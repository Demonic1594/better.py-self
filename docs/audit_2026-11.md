# Codebase audit, November 2026 (audit round 3)

A full review of `discord/` (about 119,000 lines) against the two projects it
descends from:

- **dolfies/discord.py-self** `master` at `2ba64a9` (the commit recorded in
  `.github/LATEST_UPSTREAM_COMMIT.txt`; upstream has not moved since).
- **Rapptz/discord.py** `master` at `65232c3`.

The changelog for these changes is the `Unreleased` section of
`docs/whats_new.rst`. The regression tests are in
`tests/test_audit3_round1.py` and `tests/test_audit3_round2.py`. Where a fix touches code that still matched
upstream, `docs/upstream_syncing.rst` ("Audit round 3") lists it.

## Method

1. Baseline first: the test suite, ruff 0.12 and pyright 1.1.394 were all green
   on the unmodified code.
2. Twelve read-only review passes, one per area, each told to read its files in
   full, compare them with both upstreams, and report only defects with a
   concrete trigger: gateway and voice; HTTP and tracking; the two halves of
   `state.py`; client and utils; guild, member, role and user; messages and
   `abc`; channels and threads; `ext.commands` and `ext.tasks`; flags, enums,
   permissions and audio; settings, components, webhooks and audit logs; and
   the user-account-only models (applications, store, billing and so on).
3. Every reported finding was then checked against the code before anything
   was changed. Findings that did not hold, or whose fix would change
   behaviour users may rely on, were not applied (see "Rejected" and
   "Remaining issues").
4. One class of bug found along the way (a name imported only under
   `TYPE_CHECKING` but used at runtime) was then searched for mechanically
   across the whole package with an AST scan, which found one more instance.
5. Each fix got a regression test (66 in all). 65 of them fail on the previous
   code on any Python version. The remaining one covers the
   `asyncio.TimeoutError` catch in `voice_state.py`: that class is the builtin
   `TimeoutError` from Python 3.11 on, so the test can only fail on the 3.10
   leg of CI.

## Comparison with the upstreams

**dolfies/discord.py-self:** nothing to merge. `master` is still the synced
commit.

**Rapptz/discord.py:** every bug fix since June 2025 that applies to a user
account was checked and is already present here, in the same or an equivalent
form. Among them: the stuck rate limit bucket and hashed bucket key fixes, the
heartbeat latency race, reconnecting on the default gateway after a 5xx,
closing the socket on a poll timeout, zstandard without a size header, voice
v8, FFmpeg errors reaching `after`, `MessageType.is_deletable`, the
`Message.edit` suppress default, the file upload limit, the new pin endpoints,
the thread join `PUT`, `Thread.applied_tags` for media channels, the duplicate
`ForumChannel._flags` slot, `GUILD_MEMBER_ADD` for a cached member, the audit
log role-colour and category fallbacks, the Python 3.14 annotation fixes for
flags, and the `datetime.utcnow` / `asyncio.iscoroutinefunction` removals.
Permission bit values and the `Permissions` presets are identical in all three
projects.

Several of the bugs fixed below are also present in Rapptz/discord.py or
dolfies/discord.py-self today; those are marked **(upstream)**.

## What was fixed

### Could stop or stall the client

| Area | Problem | Fix |
| --- | --- | --- |
| Gateway | A `HELLO` without `heartbeat_interval`, or a `READY` without `session_id` / `resume_gateway_url`, raised `KeyError` out of the receive loop. That is not a reconnectable error, so `Client.connect` ended. | Logged as a warning; the socket is closed and the client reconnects (re-identifying when there is no session). |
| Gateway | A handshake that failed or was cancelled (the 60 second connect timeout) left its websocket open. | `from_client` closes the socket it opened. |
| Voice **(upstream)** | A lost IP discovery datagram during a voice reconnect was awaited with no timeout: voice died silently. | 10 second timeout. `connect()` then fails and disconnects, so it can be called again; a resume gives up and disconnects; the full reconnect after other close codes retries by itself. |
| Voice **(upstream)** | A failed or cancelled `channel.connect()` left the voice client registered, so every later `connect()` raised "Already connected". Only a timeout cleaned up. | Cleanup on any failure or cancellation. |
| Voice **(upstream)** | On Python 3.10, `except TimeoutError` did not catch `asyncio.TimeoutError`, so the timeout escaped `disconnect()` before its cleanup. | Catches `asyncio.TimeoutError`. |
| Member chunks | A chunk request whose reply never arrived stayed registered forever. Every later `Guild.chunk()` joined it and never returned. | Requests track their last activity; when another `chunk()` or `fetch_members()` call finds one silent for over a minute, it fails it and sends a new request. A single call whose reply is lost still waits (see "Remaining issues"). |
| Startup | An info API answer without `browser_user_agent` was accepted, and login then failed with `KeyError`. | Treated like any other unusable answer (fallback lookup). |

### Robustness, resources and logging

- **Leaks:** files the library opened from a path stayed open when `send()`
  rejected its arguments. A finished member list scrape could delete the
  registration of a newer scrape of the same guild. A cancelled ready task
  could clear the reference to its replacement.
- **Pre-connect state:** reading your own status or activities before the
  websocket exists (after a persistence replay) raised `AttributeError`.
- **Audio:** FFmpeg failures now reach `after` through `PCMVolumeTransformer`;
  the piped-input writer thread and `__del__` no longer raise on a
  cleaned-up or half-constructed source; the Opus encoder pads a short PCM
  buffer instead of letting libopus read past its end.
- **Malformed input:** unparsable rate limit headers on a webhook response and
  a relationship that references an unknown user in `READY_SUPPLEMENTAL` no
  longer raise.
- **Log redaction:** `billing_address` and `bank` are now masked in DEBUG logs
  of request bodies.
- **Deprecation:** `request_guilds` now emits the `DeprecationWarning` its
  documentation has promised since 2.1 (it was an open item on the roadmap).

### Performance

- `utils.SequenceProxy` (behind `Client.guilds`, `Guild.members`,
  `Guild.roles` and others) never cached its copy: the `cached_property` was
  stored under a name-mangled attribute that nothing read. Every index,
  iteration, `in` test and `len`-adjacent call copied the whole collection, and
  re-sorted it for sorted proxies. It now copies once. Indexing a 200,000 item
  proxy 200 times went from about 0.13 s to about 0.002 s. **(upstream)**
- The onboarding route put the guild ID into the route template, which created
  one rate limit and telemetry key per guild. It now uses a placeholder like
  every other route.

### CI hardening

The lint, build and test workflows now run with a read-only token
(`permissions: contents: read`) and a job timeout. The wiki workflow already
declared its own permissions.

## Rejected findings

These were reported by a review pass and found not to hold, or the suggested
change would have made things worse:

- **`Role.move(above=..., below=...)` "inverted".** It is not: `above` names
  the role that ends up above the moved role, as documented, and matches
  Rapptz.
- **`ContextProperties` "bypasses its constant table".** True, but using the
  table would drop the extra keys (guild, channel and so on) of a location
  context. The current behaviour is the correct one; a comment now says why.
- **Rejecting truncated Ogg pages.** Stopping playback kills FFmpeg mid-page,
  so raising there would report an error to `after` on an ordinary skip.
- **`audit_logs(oldest_first=True)` "ignores the limit while fetching".**
  Deliberate (see the changelog): Discord returns entries newest first, so
  the oldest N can only be found by walking the range.

## Follow-up round: the remaining issues (2026-11-15)

The first version of this report ended with fourteen open items. All of them
were then worked through; the regression tests are in
`tests/test_audit3_round3.py`. Python 3.10 and 3.14 interpreters were installed
for this round, so the version-specific items were checked on the real
interpreters rather than by reasoning.

| # | Item | Outcome |
| --- | --- | --- |
| 1 | Voice handshake races | **Fixed.** A replaced UDP socket is closed, and the socket reader is woken (through a socket pair) instead of waiting out its 30 second `select()`. `_wait_for_state` registers its waiter before yielding, so a state change can't slip between the check and the wait. `disconnect()` during a handshake stops it, and `connect()` then raises `ClientException`. While fixing this, a related race turned up: when Discord moves the account mid-handshake, the voice state starts a new handshake, which cancelled the caller's `connect()` (and, since the first round's cleanup, tore the new handshake down). `connect()` now follows the new handshake. All of it is tested offline with real local UDP sockets and fakes; none needed a voice server. |
| 2 | `client_theme=MISSING` | **Fixed**, and `None` resets it too. Testing it found a larger bug: the `discord_protos` versions the requirements allow today no longer have `primary_color` or `background_gradient_angle`, so reading a set theme raised `AttributeError` and setting one raised `ParseError`. Both now work with either schema (upstream has the same bug). |
| 3 | Partial presence users | **Fixed** for presence updates only, where Discord documents the user as partial: omitted fields are kept, and a missing `username` no longer raises `KeyError`. `GUILD_MEMBER_UPDATE` carries a full user and keeps clearing fields it omits. |
| 4 | `login()` failure leaves the session open | **Fixed:** a failed first login closes and resets the HTTP session; a failed re-login of a running client leaves it alone. |
| 5 | Handlers running after `close()` | **Checked, documented.** A request they make fails at once with curl_cffi's `SessionClosed` (no retry, no hang), which a test pins. Cancelling or waiting for handlers would change how long `close()` takes, so `close()`'s docstring states the behaviour instead. |
| 6 | `AudioPlayer.set_source` | **Documented** on `VoiceClient.source`: the replaced source is not cleaned up, so it can be reused; call `cleanup()` if you won't. |
| 7 | `Loop.stop()` during the wait; `restart()` twice | **Fixed:** `stop()` ends a pending wait at once and no further iteration runs (the loop used to run once more). A second `restart()` no longer raises. `stop()` inside the body still finishes that iteration, as documented. |
| 8 | Rate limit bucket reset | **Fixed:** the request that empties a bucket returns when its response arrives; the reset wait runs in the background. Requests made meanwhile still wait for the reset, and `max_ratelimit_timeout` still refuses longer waits. |
| 9 | Typing subscriptions | **Fixed.** This was a bug, not an unclear intent: `Guild.subscribe(typing=False)` is documented as unsubscribing from the guild, but the guild stayed marked as subscribed, so `is_subscribed()` stayed true and a reconnect subscribed again. |
| 10 | `raw_thread_member_remove` | **Fixed** for uncached threads (it is documented to fire regardless of the cache, and the bounded thread cache evicts threads). It stays one event per removed member. |
| 11 | Python 3.14 forward references | **Not a defect.** Checked on Python 3.14.6: annotations resolve exactly as on 3.13, and a name defined only after the command fails at decoration on every version (as it does with string annotations). A test pins this; CI runs it on 3.10 to 3.14. |
| 12 | Quadratic markdown regexes | **Fixed**, and worse than recorded: `'<a:/' * 4000` took a quarter of a second per call and `'<a:/' * 20000` 17 seconds; now milliseconds. A differential fuzz of 400,000 inputs against the old regexes found output changes only where intended: a list marker after a blank line is now escaped on its own line (the backslash used to go on the blank line, leaving the list active), and a `<` inside an angle-bracket URL is plain text. A tighter masked-link pattern was tried and dropped because it stopped escaping links like `[x](https://host/[y)`; the link part is instead bounded at 4,096 characters, more than a message or embed can hold. |
| 13 | A lone `Guild.chunk()` with a lost reply | **Fixed:** it gives up after 60 seconds without a chunk (more above 600,000 members) with `InvalidData`, which `Guild.chunk` already documented for a missing reply. Each chunk received restarts the clock. |
| 14 | Smaller model gaps | **Fixed:** `SyncWebhookMessage.channel` honours `thread` (sync and async now share one helper); `GroupChannel` keeps its recipients on an update that leaves them out, a repeated recipient add no longer duplicates, and a removed recipient's nickname is dropped; `Widget` is hashable; the never-set `Entitlement.payment` slot is gone; guild-keyed read states are dropped with the guild. |

Also fixed in this round, from the first round's lower-priority findings: the
entitlements paginator no longer walks the whole list for `oldest_first=False`
with `after` (one request instead of one per 100 entitlements), and an activity
whose party has a null ID no longer raises while it is built.

### Still open

- **Inherited behaviour kept on purpose:** handlers are not cancelled at `close()`
  (item 5; since v2.3.3 `close()` logs a warning when it happens, see below), `set_source` doesn't clean
  up the old source (item 6), and the first round's list (the `oldest_first`
  audit-log walk, one `raw_thread_member_remove` per member).
- **Needs a live capture:** whether `Message.interaction_metadata` matches what
  Discord sends to user accounts. The two questions that also needed one
  (below) now log a warning when the unexpected case happens, so a report will
  answer them.

## v2.3.3 round (2026-11-15)

The open questions were settled the same way: check the value, and when it is
not what the library accepts, log a clear warning (once per process), skip the
value and carry on. Regression tests are in `tests/test_release_233.py`.

| Item | Outcome |
| --- | --- |
| `GUILD_MEMBER_UPDATE` user missing a field | The cached value is kept and a warning names the field. It used to reset the field (a name to `None`, say). |
| Custom theme colors | A color that isn't hex reads as `0`, with a warning. |
| `Spotify.track_url` for a local file | Returns `''` with a warning, instead of `https://open.spotify.com/track/None`. The return type stays `str`. |
| Handlers still running at `close()` | `close()` logs how many there are. A handler that calls `close()` is not counted. |
| Audit-log changes without `old_value` or `new_value` | The typings mark both as optional (Discord omits them), and a missing one reads as `None`. |
| Stress benchmark soak plateau | The gate now counts live allocated blocks (`sys.getallocatedblocks()`), not RSS. RSS is printed for information. |
| `ActivityType.unknown` | Added (`-1`); it was documented but missing. Sending it sends `playing`, with a warning. |
| `on_raw_typing`, `on_raw_thread_update` | Ported from Rapptz (planned for v2.3.4, moved up). `on_raw_typing` is opt-in with `enable_raw_typing`. |

## Verification

Run on the v2.3.3 code (Python 3.13 with orjson, unless noted):

- `ruff format --check` and `ruff check` with ruff 0.12: clean.
- `pyright discord` with pyright 1.1.394: 0 errors.
- `python -m pytest -q`: 831 passed, 1 skipped (707 before the audit). The
  tests of each round fail on the code before it, except the guards that pin
  behaviour that must not change, which say so.
- The audit test files plus the tasks, rate limit, reconnect and utils tests on
  Python 3.14.6 and 3.10.20: all pass, as do the v2.3.3 tests. Neither
  interpreter has orjson, so these ran with the stdlib JSON parser. On 3.10, the
  first round's voice timeout test was also confirmed to fail on the code before
  the audit.
- The new tests and the log redaction and rate limit tests with the stdlib JSON
  parser: pass.
- Sphinx build with `-n -W`: clean. The wiki link check and the README parse:
  clean.
- Memory benchmark (`tests/memory_bench.py --members 50000`): 45.27 MiB
  retained, the same as before the audit.
- Stress benchmark (`tools/stress_bench.py`): every gate passes. The soak
  plateau gate now counts live allocated blocks (+0.34% against a 2% limit);
  RSS grows by 10.8 MiB over the same window, as it did before the audit,
  which is the allocator keeping freed arenas.
